AIS Day

Consequence Engine & Perspective Mesh — a research layer that learns from outcomes instead of generating opinions.

This page documents a seven-layer reasoning system. It is a research artifact, not a live trading engine. The goal is simple: turn AI-generated perspectives into checked, comparable, improvable decisions.

repo-firstevidence-before-actionno destructive defaults

The seven layers

1
Executor — Proposes a concrete, verifiable action and lists assumptions.
2
Verifier — Blocks unverified or unsafe assumptions. Gatekeeper.
3
Investigator — Finds blind spots, rollback plans, side effects.
4
User-defined roles — Domain lenses: cost, infra, legal, etc.
5
Report / site — Renders the structured result. Not the source of truth.
6
Consequence Engine — Records outcomes and weights each role's accuracy over time.
7
Perspective Mesh — Runs the same task through multiple models and surfaces consensus, dissent, and shared assumptions.

Why this matters

  • Right now, most AI systems produce opinions. Nothing checks whether the opinion was right.
  • Layer 6 closes the loop between perspectives and reality.
  • Layer 7 turns disagreement into signal instead of noise.
  • The shared assumptions across independent instances are the most dangerous blind spots.

Repository

Source of truth lives in the CoreIntent repo under ops/guard/:

  • perspective-engine.sh — Layers 1–4
  • consequence.sh — Layer 6 ledger and scoring
  • mesh.sh — Layer 7 multi-model comparison
  • jev-schema.yaml — Typed output schema
  • jev-validator.sh — Validate outputs

policy.yaml

policy:
  destructive_requires_approval: true
  verify_before_execute: true
  record_consequences: true
  weight_bounds: [0.2, 2.0]
  weight_delta: 0.1

Example: record and score

./consequence.sh record \
  --task-id vds-push-001 \
  --result success \
  --notes "SSH succeeded, checksum matched" \
  --verifier correct

./consequence.sh score
./consequence.sh report --role verifier

Example: mesh

export MESH_CMD_CLAUDE="ollama run qwen3:8b-64k"
export MESH_CMD_GROK="ollama run hermes3:8b"

./mesh.sh \
  --problem "Should we rebuild the nginx config for aisday.com?" \
  --models "claude,grok"

Output shape

{
  "consensus": "NEEDS-EVIDENCE",
  "dissenters": ["grok"],
  "shared_assumptions": [
    "nginx config exists",
    "operator has not explicitly approved the change"
  ],
  "confidence": 0.5
}

Example run

Task: Push a new build to the VDS.

RoleOutputGate
ExecutorProposed: rsync build to 100.64.0.2:/var/www/coreintent—
Verifierneeds-evidence: human disposition missing, no checksum yetblock
InvestigatorBlind spots: rollback, downtime, disk at 87%—
Cost LensUse existing VDS; no paid API calls requiredask
Infra LensTarget alias ssh vds; verify nginx reload pathask

Judgment: needs-evidence. The operator must confirm disposition before the action proceeds.

After execution: run consequence.sh record so the Verifier weight updates.

Deploy

This page is a thin renderer. The authoritative system is the repo guard layer.

  • Next.js app: place public/aisday.html and it is served at /aisday.html.
  • VDS / nginx: copy public/aisday.html to a static vhost root for aisday.com.
  • Cloudflare Pages is intentionally not used for this artifact per fleet rules.

Build the repo first:

npm install
npm run build
./scripts/audit.sh
